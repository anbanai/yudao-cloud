# 易宝多商家支付验收与审查记录

审查基线：后端 `54cead8d6`、管理后台 `2459b7a6`、小程序 `c0067dc6`。目标为各仓库本地 `teaworthshare`；本次不推送远程。实现与审查在隔离工作区完成，其他开发任务的未提交改动在集成时单独保留。

## 审查修复

独立审查与回归修复涵盖：把支付成功误作清算成功、并发清算重复查询、线程池拒绝阻碍 ACK、退款整数溢出、人工重试降级成功状态、旧回调入口绕过资金校验、缺失原资金快照仍开始归还、商家事件键不足、跨渠道同事件号错误去重、账单日期宽松纠正、缺失加密回调原文。

最后一轮进一步修复：退款失败后释放已归集额度导致重复归集；退款和归还两种迟到通知交错覆盖人工状态；归还更新清除退款成功时间；终态退款缺乏原提交证据时仍允许重试；配置相等比较触发运行时密钥读取；后台列表/详情/上传/保存的旧结果覆盖新对象。退款时序和前端异步缺陷都有实际 RED 后的 GREEN 回归记录。

基线商品实现已引用但缺少声明的 Brand/SPU 合同也作最小补全，使隔离基线能够完整编译；可用商品查询绑定状态与删除参数，避免硬编码数据库布尔字面量。没有把其他任务的商家申请、商家工作台和自助账户实现纳入本次提交。

## 最终验证

后端统一使用 Java 17，以下结果来自本次隔离工作区的最终版本。

- 支付全量：397 个测试，0 失败、0 错误，其中 35 个为基线既有跳过项；实际执行 362 个。
- 商品与交易全量：商品 93 个、交易 176 个，共 269 个测试，0 失败、0 错误、0 跳过。
- 共享工作区商家新审批入口兼容：7 个审批事务用例，加 12 个入网及 5 个敏感资料加密用例，共 24 个，全部通过；审批与入网任务同事务提交/回滚，没有重复 hook。
- 聚合服务打包：42 个 reactor 模块 `mvn -pl yudao-server -am package -DskipTests` 通过。
- 管理后台：29 个测试、完整类型检查、限定文件 ESLint、生产构建通过；使用项目支持的 Node 24。
- 小程序：支付方式筛选、易宝提交/失败分发检查通过，微信小程序生产构建通过。
- SQL：五份 PostgreSQL 脚本经原生 PostgreSQL 解析器解析通过；资金脚本在 H2 PostgreSQL/Oracle 兼容模式执行通过。字段与唯一索引审查覆盖八种脚本。没有宣称八种厂商原生数据库执行通过。

支付现有真实外部支付集成测试及原先标记禁用的服务测试保持原禁用状态；上述 35 个跳过项已单独列出。管理后台生产构建的大包提示和小程序既有循环分块提示不属于本次新增功能错误。

## 环境验收边界

本次没有真实易宝商户与环境证书，不能把本地官方 SDK 契约测试当作真实资金联调。平台收款商编角色、子商户权限、手续费承担/补贴、接收方上限、回调枚举、实际日账单及已分账退款归还顺序必须在易宝测试环境确认。新渠道与全额分账保障默认关闭，未完成确认不得生产放量。

原生数据库专项部署、真实商户入网、微信支付权限和生产资金灰度属于部署前置条件。代码合并保留这些关闭条件及历史任务，不表述为生产已经验收。
