# 运费模板区域匹配与 0 值配置设计

## 背景

当前快递运费模板在两处表现不符合配置预期：

1. 配置新疆收费、其他区域包邮后，选择新疆地址可能没有计算出运费。
2. 后台运费金额字段不能方便地配置为 0。

运费模板由模板主表、区域收费配置和区域包邮配置组成。价格计算使用收货地址的末级区域 ID，而配置区域可能来自省、市或末级区域；收费和包邮配置还可能在同一具体区域同时存在，用于表达“满足条件后包邮”。

## 目标

- 允许运费相关金额配置为 0，并在后端和后台表单保持一致。
- 收货地址使用末级区域 ID 时，能够命中模板配置的省级或市级区域。
- 支持“新疆收费、其他地区包邮”以及“同一区域收费，满足门槛后包邮”两种语义。
- 对非法负数和会导致计算异常的数量配置进行校验。
- 不修改现有数据库字段类型，不要求数据迁移。

## 规则语义

### 费用与门槛

- `startPrice`（起步价）、`extraPrice`（续件价）取值范围为 `>= 0`，单位仍为分。
- `freePrice`（包邮金额）、`freeCount`（包邮件数）取值范围为 `>= 0`。
- 包邮条件继续使用“金额和数量同时满足”的语义：订单金额 `>= freePrice` 且计费数量 `>= freeCount`。
- `freePrice = 0` 或 `freeCount = 0` 表示对应条件不设门槛；两者同时为 0 时，匹配该区域的订单直接包邮。
- `startCount`、`extraCount` 必须大于 0，避免续件计算除以 0；模板排序和名称规则保持现有行为。

### 区域匹配

匹配收货地址时沿地区树从末级地址向上查找配置区域，因此配置省级区域可以覆盖其下属城市和地区。对同一模板、同一配置类型，选择匹配程度最高的规则：

- 末级区域精确匹配优先于市级、省级和更高层级匹配。
- 收费规则和包邮规则分别选择各自最具体的匹配项。
- 如果收费规则比包邮规则更具体，则收费规则覆盖更宽泛的包邮规则，支持“全国包邮但新疆收费”。
- 如果收费和包邮规则匹配程度相同，则同时保留两者，继续按包邮门槛判断，支持“新疆收费，满额包邮”。
- 没有任何匹配规则时，继续返回模板未找到错误，避免静默按 0 运费下单。

## 实现范围

### 后端

- 在运费模板请求 VO 上增加非负校验；对首件/续件数量增加正数校验。
- 在模板转换/匹配层复用 `AreaUtils` 的地区树关系，计算候选规则的具体程度。
- 在返回计算 BO 时保留收费与包邮的有效组合，并按上述优先级消除宽泛包邮规则对更具体收费规则的覆盖。
- 保持现有价格计算、订单分摊和数据库结构不变。

### 后台管理

- 运费模板新增和编辑表单中的金额输入允许 0，最小值改为 0；负数前端校验与后端一致。
- 首件数量、续件数量仍限制为大于 0。
- 包邮金额和包邮件数允许 0，并在表单提示中表达“0 表示不设该门槛”。
- 区域选择和回显保持现有数据格式，不要求一次性重建历史模板。

当前工作区的 `yudao-ui` 目录只包含各管理端项目的 README，没有实际前端源码；实现阶段需要在可用的后台管理端源码目录同步修改，若该目录仍不可用，则先完成后端并明确列出前端文件缺口，不伪造已完成的管理端改动。

## 测试策略

- 转换层测试：末级地址命中省级收费配置；同层级收费/包邮同时命中时保留包邮门槛；更具体收费覆盖宽泛包邮；无匹配时不生成模板 BO。
- 价格计算测试：新疆配置收费、其他区域包邮时，新疆产生起步运费，其他区域运费为 0；起步价和续件价为 0 时计算结果保持 0；包邮门槛为 0 时按规则直接包邮。
- 参数校验测试：所有费用字段接受 0、拒绝负数；首件数量和续件数量拒绝 0 和负数。
- 管理端测试或静态检查：金额输入最小值为 0，数量输入最小值为 1，提交请求字段与后端 VO 一致。

## 错误处理与兼容性

- 历史数据中的 0 值无需迁移即可读取和计算。
- 历史数据中的负数不在读取时自动修正；编辑或保存时由校验阻止继续写入。
- 区域树中不存在的配置 ID 不参与父级匹配；若收货地址最终没有任何有效规则，继续走现有“模板未找到”错误路径。
- 不改变同一具体区域“收费 + 满额包邮”的既有业务含义。
