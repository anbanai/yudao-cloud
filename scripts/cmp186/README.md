# CMP-186 隔离验收

仅供合成库验证，**不是上线安装器**。从交接单的精确候选 SHA 建干净 checkout；用 JDK 17、Maven 3.9.9、Node、本机 Docker 和已有的 `mysql:8.0.44` 镜像。设置 `BYTE_BUDDY_AGENT` 为本机 `byte-buddy-agent-1.17.8.jar` 的绝对路径，必要时在命令尾传 Maven `-s /path/to/settings.xml`。保存版本和脱敏计数，不保存业务行或口令。

```sh
git rev-parse HEAD
bash scripts/cmp186/mysql-product.sh
bash scripts/cmp175/mysql-flow.sh
```

第一个脚本使用独立容器、合成菜单和最小商品读写角色，不写交易表。测试组合 DDL、品牌新装/旧值保留/双列拒迁、两个连接竞争同一有效模板并释放、拒绝越租户/已删/计费异常/非法配送、纯自提、末步回滚不建档、成功绑定 1 条、撤授权后数据不变。建档服务使用合成 SQL 写入桩，不是整套在线商城。第二个脚本在另一个一次性库做领取事务与索引迁移正反例，11 项必须无跳过。没有授权的实际服务数据源拓扑/权限仍需交付方用真实测试角色核对；物理分库不通必须停，不能去掉锁读。

**迁移次序**：停导入、领取及旧写者，备份可恢复的数据、应用和密钥；盘点等级、账本、来源授权、父菜单 209 和 R4/R5 既有表。基础账本及积分批次就绪 → `sql/mysql/member_youzan_import.sql`（已装核对不重放）→ `cmp158/02-member-recovery-floor.sql` → `cmp172/01-youzan-claim-receipt.sql` → `cmp172/02-youzan-recovery-source.sql`。无凭证历史、重复来源或结构不符即停；绝不删历史绕过。随后新装运行 `V20261125_01__product_youzan_import.sql`（已运行 R4 的库核对三表及菜单后跳过），再运行 `cmp158/01-brand-detail.sql`。后面路径均相对 `sql/mysql`。若存在任一旧列，先核实其为非空布尔、默认关并备份各值；仅 `show_on_detail` 时原样改名，仅 `show_in_detail` 不动；两列并存拒迁，保留原值提交人工对账，不做 OR 或覆盖。双列拒迁会保留临时存储过程，整改后仅清理该过程再复核。核对可信来源、专用 32 字节 Base64 商品预览密钥及角色、租户/商家/操作人 grant，最后才开放授权的测试入口。

**停用/回退**：先封禁领取和导入写接口、停旧客户端写，撤导入角色、菜单和 grant，再切回相容应用。保留批次、快照、领取凭证、来源唯一键、积分批次/流水、等级下限、商品映射及品牌列。若旧应用需要 `show_on_detail`，须全停写并确认仅新版列及旧版本依赖，备份后逆向 RENAME；不可二列并行写。切回无幂等保护的领取版本时继续封禁领取，不能仅回滚应用便重开。核对余额、流水、SKU/库存及品牌值，不倒扣、不中途删表，不触碰订单。物理结构清理另行审批。
